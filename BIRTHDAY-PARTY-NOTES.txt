Adding a gif: drop it in assets/birthday/ AND add its file name to manifest.json
(a static site cannot list a folder, so the list is how the app learns the names).

Preview now, no data needed
  open the app with ?birthdaydemo=members   reads members-demo.json and celebrates whoever has a
                                            birthday TODAY (device date). The 3 fake birthdays are 13 Nov,
                                            so on any other day use the two options below.
  open the app with ?birthdaydemo=1               sample names
                    ?birthdaydemo=Ann,Marcus,Joy  your own names
  or in the browser console: BirthdayParty.demo()

What it does
  - Gif: shuffled deck from the manifest, changes every 10 s, no repeats until all used.
  - Names: shuffled, one at a time, 3 s each. Fewer than 4 names: the time per name
    is stretched so the party lasts at least 10 s (1 name = 10 s, 2 names = 5 s each).
  - Row fades away after the last name; it does not return until the app is reopened.
  - Tap/click the row: popup with the gif, HAPPY BIRTHDAY, names A-Z, on assets/birthday.gif.
    Close with X, the dark area, or Esc. The clock pauses while it is open.
  - The clock only runs while the row/button is showing (pauses in Books/Videos/Images,
    in a hidden tab, behind the loading screen and while the popup is open).
  - Gradient fallbacks: gold disc if a gif fails (row, button and popup); the popup card is a
    teal gradient under birthday.gif, so it simply stays teal if that gif fails.
    The gifs are transparent, so the gradients only show on failure.

Where it goes (the page is measured, first layout that really fits wins)
  1. SIDE    room left of the centerpiece (desktop, laptop, landscape tablet/phone):
             row from the left edge to 18px left of the centerpiece, 6px above the doors.
             The popup also opens in that left space (no dimming), so the centerpiece
             stays visible while the list is read. Tap outside / X / Esc closes it.
  2. BELOW   no room beside it but a clear strip between the centerpiece and the doors
             (phones, portrait tablets): row sits in that strip, 6px above the doors, never
             over the centerpiece, and stops 8px left of the share button when that button is
             above the doors (phones). Popup is centered.
  3. BUTTON  neither fits (short phones, near-square windows, small landscape phones):
             a birthday button, 60x60 like the share button and its horizontal mirror
             (same padding, hover and press feel; left side instead of right). Uses
             assets/birthday-icon.gif, or a gold gradient disc with a star if it cannot load.
  The row and the button both show for 10 seconds only (the row longer when there are many
  names: 3 s per name), fade in/out, then are gone until the app is reopened. The button's
  10 s is BUTTON_MS at the top of js/birthdayParty.js.
  Rows shrink with their space (smaller gif/text, then stacked). The layout is re-chosen
  when the window is resized or rotated.
  The decision is chooseMode() / choosePopup() in js/birthdayParty.js (pure functions,
  covered by birthdayParty.test.mjs, including "never over the centerpiece" at every size
  from 300x400 to 1920x1300).

Text
  White; text-shadow is your 0 2px 3px rgba(0,0,0,.55) plus a faint wide halo
  (0 0 10px rgba(0,0,0,.3)) because the water background is light. The gif has a tiny
  drop-shadow for the same reason. Both are one line each in birthday-party.css
  (--bp-shadow, and the filter on .bp-gif img) if you want them removed.

Cost / risk
  With no names nothing runs at all (no request, no timer, no DOM). With names: one small JSON
  request plus the gifs, one 200 ms timer, two elements added inside #frontPage. It does not touch
  the centerpiece, doors, share button or any front-page script.

Rollback: remove the <link> and <script> lines from index.html.

NEXT STEP (data) - how it will plug in
  The only call needed is  BirthdayParty.setCelebrants(["Ann","Marcus",...]).
  Plan: the Worker reads the members file from the private R2 bucket, works out who has a birthday
  today (in Trinidad time), and returns ONLY display names. Phone numbers, emails and birth years
  never reach the browser. Anniversaries can reuse the same row/popup with a different title.
